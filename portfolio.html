PROJECT OVERVIEW

從求職情境出發，
整理 JD 與個人能力的關係。

作品類型：個人專案
AI 求職輔助 Web App

01 / PROBLEM

職缺資訊多，
比較過程費時又不完整。

閱讀不同職缺時，需要整理工作內容、必要能力、加分條件與工具要求，再逐項回想自己的經歷。資料一多，容易忽略能力證據，也不容易分辨哪些只是尚未確認。

02 / SOLUTION

把需求拆成可閱讀、
可補充的能力配對。

使用者輸入文字 JD 或職缺截圖，並建立可重複使用的求職 Profile。AI 依據 Profile 中明確提供的資訊分析需求，產生證據、待確認項目、應徵策略與自我推薦草稿。

PRODUCT求職能力分析 Web App
INPUTJD 文字或職缺截圖 × Profile
OUTPUT配對狀態、應徵建議、自我推薦

  2. 02

  3. 03

    檢視能力配對

  4. 04

  5. 05

KEY FEATURES

功能圍繞「看懂需求、找到證據、採取下一步」。

01

JD Requirement Analysis

拆解工作內容、能力要求與加分條件，支援文字與截圖輸入。

02

Reusable Profile

以技能、證照、經驗、作品與優勢建立求職能力資料。

03

Profile Matching

將 JD 中的要求逐項比對 Profile，並呈現支持判斷的資料。

04

Requirement Decomposition

複合要求拆成子項，區分已有證據與尚待確認，避免部分符合被視為全部符合。

05

Profile Supplement

使用者自行補充相關能力，更新 Profile 後重新分析，不由前端預設符合。

06

Application Strategy

整理優先主打、可以補強、應徵呈現方式與只根據已確認資訊撰寫的推薦內容。

AI WORKFLOW DESIGN

AI 判斷邊界設計
Evidence-based AI

開發過程中最重要的設計問題，不只是如何呼叫模型，而是如何避免模型把「沒有資料」說成「沒有能力」。

因此，分析結果要指出依據和不確定性。複合要求會拆解子項；使用者補充資料後，也必須重新分析，不能由前端把狀態直接改成已符合。

UI / UX DECISIONS

把複雜分析變成可以快速掃讀的資訊。

以狀態、證據與下一步建立閱讀層級，讓使用者能先看全貌，再查看細節。

01

狀態顏色一致

綠色呈現已符合、藍色呈現可延伸、橘色呈現待確認，支援快速辨認狀態。

已符合可延伸待確認

證據與未知分開

能力卡片同時呈現判斷說明、已有證據與尚待確認的子要求，避免過度簡化複合條件。

已有證據尚待確認
03

就地補充 Profile

待確認項目可開啟補充視窗，選擇 Profile 類型並由使用者自行輸入資料。

＋ 補充相關能力 取消　加入並重新分析

控制閱讀負擔

將求職建議整理為優先主打、可以補強、應徵呈現方式三部分，協助聚焦當前職缺。

從問題定義到上線展示，
逐步驗證產品方向。

需求、判斷規則、測試情境與迭代方向由我規劃；ChatGPT / Codex 協助實作與測試。

  1. 01

    Problem Discovery

    從實際求職中閱讀大量 JD 的情境，整理資訊多且難以逐項比對的問題。

  2. 02

    Product Planning

    規劃 JD、Profile、能力比對、結果、資料補充與自我推薦的產品流程。

  3. 03

    UI & Interaction Design

    設計結果資訊層級、狀態卡片與 Profile 補充互動，降低閱讀與操作負擔。

  4. 04

    AI Workflow Design

    制定 Evidence-based AI、Confirmed / Inferred / Unknown 與複合需求拆解原則。

  5. 05

    AI-assisted Development

    使用 ChatGPT / Codex 協助程式開發、測試與迭代；產品需求與驗收方向由我定義。

  6. 06

    Testing

    測試 JD × Profile、複合需求、Profile 補充與重新分析、錯誤處理及使用限制。

    以 Git / GitHub 管理版本，部署至 Render，提供可實際操作的 Portfolio Demo。

PUBLIC DEMO

把安全與成本控制納入展示版本。

公開 Demo 需要可操作，也需要清楚的使用邊界。API Key 留在伺服器端，並以使用限制降低公開展示期間的濫用與額外成本。

01Server-side API Key

透過伺服器環境變數管理，不送往瀏覽器。

02Usage Limits

分析端點設有 Rate Limit 與每日 Demo 次數上限。

03Input Protection

限制 JD、Profile、圖片與整體 Request Body 大小。

04Resilient API

設定 OpenAI Timeout、Retry 與通用錯誤處理。

05Deployment Health

由 Render 環境變數提供設定，並提供 Health Check。

PROJECT LEARNINGS
