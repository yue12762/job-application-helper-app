About This Project

專案介紹

Problem

求職 JD 資訊很多，但不容易快速判斷自己是否適合

求職者閱讀職缺時，常需要同時整理工作內容、技能需求與加分條件， 再與自己的經歷進行比對。當職缺資訊較多時，很難快速判斷哪些能力已經符合、 哪些可以延伸，以及哪些資訊仍需要確認。

Solution

將 JD 與個人 Profile 轉換成可理解的能力比對

Job Application Helper 將職缺 JD 與使用者建立的求職 Profile 進行分析， 把需求整理成「已符合、可延伸、待確認」三種狀態， 並提供證據、尚待確認項目、應徵策略與自我推薦內容。

Key Features

01

JD Requirement Analysis

拆解職缺工作內容與能力要求。

02

Profile Matching

將使用者能力、經歷、證照與專案作為比對依據。

03

Evidence-based AI

AI 不將沒有資料的能力直接判定為不足，而是標記為「待確認」。

04

Application Support

依據分析結果整理應徵重點與自我推薦內容。

FROM IDEA TO DEMO

Development Process

開發流程

  1. 01

    Problem Discovery

    從求職過程中閱讀大量職缺 JD 的情境出發， 思考如何更快速整理職缺需求並與個人能力進行比對。

  2. 02

    Product Planning

    規劃 JD 輸入、求職 Profile、能力比對、 應徵策略與自我推薦等核心使用流程。

  3. 03

    UI & Interaction Design

    設計資訊層級、能力狀態卡片與 Profile 補充流程， 讓複雜的 AI 分析結果更容易閱讀與操作。

  4. 04

    AI-assisted Development

    使用 ChatGPT / Codex 協助程式開發與測試， 並自行定義產品需求、AI 判斷規則、測試情境與迭代方向。

  5. 05

    Testing & Deployment

    測試 JD × Profile 比對、Evidence-based AI、API 錯誤處理與使用限制， 並將 Web App 部署為可實際操作的 Portfolio Demo。

Project Learnings

專案收穫

01

從功能需求轉換成產品流程

透過實際製作 Job Application Helper，練習將「分析職缺」這個想法拆解成 JD 輸入、Profile 建立、能力比對、結果呈現與補充資料等完整流程。

02

設計 AI 的判斷邊界

在開發過程中發現，AI 容易將缺少資料誤解為使用者不具備能力。 因此建立「已符合、可延伸、待確認」與 Evidence-based AI 規則， 讓分析結果更重視資料證據與不確定性。

03

從 Prototype 到可操作 Web App

除了 UI 與 AI 功能，也實際處理 API 串接、輸入限制、Rate Limit、 錯誤處理與 Render 部署，理解一個 AI Prototype 要成為可供他人操作的 Web Demo， 還需要考慮安全性、成本與使用體驗。
